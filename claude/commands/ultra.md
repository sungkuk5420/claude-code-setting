# /ultra — ultracode 모드로 작업 실행

사용자가 이 작업을 **ultracode**(멀티에이전트 워크플로 오케스트레이션 + 최대 철저함)로
처리하길 **명시적으로 옵트인**했다. 아래 작업을 그에 맞게 **풀로** 수행한다.
이 `ultracode` 호출은 Workflow 도구 사용에 대한 명시적 사용자 승인이다.

## 작업

$ARGUMENTS

## 실행 지침 (ultracode)

1. **Workflow 도구로 오케스트레이션한다.** 작업을 분해해 병렬 fan-out(탐색·구현·검증)으로
   처리한다. 독립 작업은 동시 실행, 다단계는 pipeline. **적대적 검증(adversarial verify)** 단계를
   포함해 결과를 교차 확인한다. 단순 단일 편집이 아니라면 솔로로 처리하지 말고 워크플로를 구성한다.
2. **규모에 맞게 스케일한다.** 작업이 클수록 finder/verifier 풀을 넓히고 검증 라운드를 늘린다.
   여기서는 **토큰 비용보다 철저함·정확성을 우선**한다(전역 규칙 PW-5 의 "가볍게"를 이 호출 한정으로
   해제).
3. **탐색은 Explore 서브에이전트에 위임한다(PW-1).** 메인 컨텍스트를 lean 하게 유지.
4. **리뷰는 code-reviewer 에이전트로 보낸다.** Edit/Write 는 도구 수준에서 제거됐고 Bash 는 에이전트 훅
   (`reviewer-readonly.cjs`)으로 조회 명령만 허용된다. 리뷰 결과는 diff 로 재확인한다(PW-8). partial 로 끝난
   리뷰는 판정으로 쓰지 않고 diff 를 쪼개 재디스패치한다.
5. **안전 레일은 그대로 유지한다(PW-2).** 보호 브랜치(main/master, `DEPLOY-*`) 커밋·푸시 금지(훅이
   하드 차단), 파괴적 git 은 permissions.deny(필요하면 사용자가 직접 실행), 외부 시스템 쓰기·MR 머지는 사용자 확인, push 는 작업 완료 후 사용자 지시가
   있을 때만. 서브 브랜치 커밋은 무프롬프트 자율.

## 주의 (정직 고지)

- 이 명령은 **워크플로 오케스트레이션**을 켠다. ultracode 의 나머지 절반인 **effort 슬라이더(xhigh)**
  자체는 슬래시 명령으로 신뢰성 있게 못 바꾼다. 정말 최대 추론 깊이까지 원하면 UI 에서 effort 를
  올려두고 `/ultra` 를 호출하라.
- 작업이 실제로는 사소하면 과잉 오케스트레이션 대신 그 사실을 한 줄로 알리고 가볍게 처리한다.
