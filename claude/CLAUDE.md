# 개인 Claude Code 전역 규칙

> 어느 레포에서든 참인 협업·안전 규칙만 담는다. 프로젝트 전용 규칙(코딩 컨벤션, 도메인 규칙,
> 작업 로그 위치)은 각 레포의 `CLAUDE.md` / `.claude/rules/` 에 둔다.
> 이 파일은 기본 동작과 스킬(superpowers 등)보다 우선한다. 강제(보호 브랜치 차단·검증 게이트·비밀 파일
> deny)는 훅과 권한 설정이 맡고, 이 파일은 모델 지시다.

---

## WP-0. 답변은 항상 한국어

사용자가 읽는 모든 텍스트는 예외 없이 한국어. 코드 식별자·경로·명령어·에러 원문은 그대로 둔다.
커밋 메시지·코드 주석도 한국어. 하네스 안내문이 영어라도 답변 언어는 사용자를 따른다.

---

## WP-1. 바로 착수

계획 승인을 기다리지 않는다. 조사 → 구현 → 검증까지 진행한 뒤 결과와 diff 로 사후 보고한다.

- 선택지가 갈리면 합리적인 쪽을 골라 진행하고 그 선택과 근거를 보고에 한 줄 남긴다.
- 사용자 지시가 차선이라고 보이면 대안을 한두 문장으로 제시하되, 고위험(PW-2)이 아니면 진행한다.
  사용자가 재확인하면 그 결정대로 한다.
- 되묻는 것은 **사용자만 아는 정보**(비즈니스 의도, 우선순위, 외부 사실)로 좁힌다. 파일·함수·상태의
  위치, 외부 값은 Grep/Read/실측으로 확증한다. 추측으로 코드를 쓰지 않는다.
- 멈추는 것은 PW-2 의 고위험 목록과 PW-3(원본 보존) 뿐이다.

## PW-1. 병렬 실행과 컨텍스트 관리

- 의존성 없는 도구 호출은 한 메시지에서 병렬로. 앞 결과가 다음 입력인 단계만 직렬.
- 긴 명령은 background 로 돌리고 그동안 다른 일을 한다.
- **여러 파일을 훑는 탐색은 Explore 서브에이전트에 위임**하고 결론만 받는다. 메인 대화에 파일 원문을
  쌓지 않는다. 예외: 어느 파일·심볼인지 아는 단일 조회, 한두 번의 Grep, 파일 수정 작업.
- 토큰을 아끼려고 확인을 생략하지 않는다. 정확성 > 속도 > 토큰. 단, 메인 컨텍스트 비대화는 비용이다.
- **컴팩션 시 보존:** `/compact`·자동 컴팩션 요약에 이 세션이 수정한 파일 목록, 실행할 검증 명령, 루프 계약
  (목적/범위/종료조건), 미커밋 변경 상태, 시도 횟수를 반드시 남긴다. 컴팩션·재개 직후에는 요약을 믿지 말고
  SessionStart 훅이 재주입한 상태와 `git status`, `<repo>/.claude/loop-contract.md`(있으면)를 다시 읽고 이어간다.

## PW-2. 위험 작업 게이트

**판단 기준:** 실행 후 30초 안에 되돌릴 수 있고 로컬 한정이면 진행. 아니면 확인.

**확인 없이 진행:** 파일 읽기·편집, 탐색, 빌드·테스트·린트·타입체크, `npm install` 류,
git 조회, **서브 브랜치 커밋**("커밋할까요?"를 묻지 않는다. 이 규칙이 기본 동작 "커밋은 요청 시에만"보다
우선한다).

**확인 후 진행:** 파일·디렉토리 삭제, **push 전부**(작업 중 push 금지, 모든 작업이 끝난 뒤 사용자가
"푸시"라고 했을 때만), 미설치 패키지 즉시 실행(`npx -y`, `pnpm dlx`, `yarn dlx`), 외부 시스템 쓰기(MR/PR 머지,
이슈·코멘트, 메시지 전송, 외부 API 쓰기), 인증·권한·CI/CD 수정.

**절대 금지:** 보호 브랜치(main, master, `DEPLOY-*`)에 직접 커밋·푸시. 훅 `block-main-commit-push.cjs`
가 하드 차단한다. 보호 브랜치에 있으면 `git switch -c feat/...` 로 서브 브랜치를 만든 뒤 작업한다
(`checkout -b` 대신 `switch -c`: 파일을 덮어쓰지 않고 권한 매처에 깔끔히 걸린다). 실수로 커밋했다면
`git revert` 후 전용 브랜치로 분리한다.
파괴적 git(`reset --hard`, `push --force`/`--delete`, `branch -D`, `clean -f`, `commit --amend`, `rebase`,
`checkout --`/`restore --worktree`/`switch --discard-changes`, `--no-verify`)은 permissions.deny 로 Bash·PowerShell
모두 막혀 있다 — 필요하면 사용자에게 직접 실행을 요청한다. `.env`(`.env.example`·`.sample`·`.development`·`.test`
제외) 읽기는 permissions.deny 로 막혀 있다(Edit 는 막지 않으니 비밀 파일은 쓰지도 않는다). 필요한 값은 사용자에게 요청한다.

**예외:** 시작 브랜치가 `david` 같은 개인 통합 브랜치면 새 브랜치를 만들지 않고 거기에 커밋한다.
그 브랜치의 작업 완료 시점 push 는 별도 지시 없이 1회 진행한다(ask 게이트가 뜨면 그 확인만).

## PW-3. 원본 보존 (Diff-First)

**발동:** 사용자가 원본·백업·이전 버전을 함께 주면서 정리·리팩토링·마이그레이션·재작성을 지시했을 때.
파일 종류 불문.

**원칙:** 명시적으로 "삭제/통합/축약"을 지시받지 않은 항목은 결과물에 전부 보존된다. "정리"는 구조와
포맷의 일이지 내용 누락 허가가 아니다.

**절차(쓰기 전):** ① 원본의 의미 단위 목록(코드: export·함수·분기·import / 설정: 최상위 블록 /
문서: H1~H3 / 데이터: 키) ② 결과의 같은 목록 ③ 추가·제거·변경을 한 줄씩. 제거는 "왜 + 어느 지시
근거" 병기 ④ **사용자 승인 후에만 파일 쓰기.** WP-1 의 유일한 사전 승인 예외다.

**금지:** "반복적이라서/안 쓸 것 같아서/더 깔끔해서" 식 임의 제거. 원본을 받고도 대조 없이 새로 쓰기.
"전체적으로 정리했습니다" 식 보고. 인프라 설정·보안 코드·스키마·배포 설정은 더 엄격히.

근거: 누락은 무성으로 일어나고, 한 블록 누락이 서비스 다운으로 직결된 적이 있다.

## PW-4. 명령은 plain 하게

`$(…)`·`${…}`·백틱·변수가 섞인 명령은 권한 매처가 매칭하지 못한다(Manual 모드는 프롬프트, auto 모드는
분류기 심사 대상).

- `${...}`, `$(...)`, 백틱, `; echo EXIT` 장식 금지. 출력과 종료코드는 도구가 보여준다. `2>&1` 은 PowerShell
  도구에서 NativeCommandError 를 만들므로 쓰지 않는다.
- `cd X && cmd` 는 X 가 작업 디렉토리 밖(워크트리 등)이거나 뒤에 git·리다이렉션이 오면 프롬프트를 부르고,
  PowerShell 도구에서는 `&&` 자체가 파서 오류다. 항상 절대경로를 쓴다: `npm run typecheck --prefix <경로>`,
  `npm ci --prefix <경로>`(allow 규칙 `npm ci:*` 에 걸리도록 서브커맨드를 앞에), `git -C <경로> status`.
  정말 필요하면 `cd` 는 단독 호출로.
- `| tail` 정도의 파이프는 허용. PowerShell 의 `$LASTEXITCODE` 도 같은 이유로 뺀다(이 규칙은 Claude 가
  실행하는 명령에 대한 것이고, 사용자가 손으로 돌리는 스크립트엔 해당 없다).

## PW-5. 적응형 effort

- 일상 대화·단순 편집·좁은 탐색은 과한 추론이나 오케스트레이션 없이 가볍게.
- 광범위·고복잡 작업(다파일 리팩토링, 시스템 설계, 교차 레포, 대규모 감사)만 깊이·병렬성을 올린다.
  그 규모면 `/ultra`(Workflow 오케스트레이션)를 옵트인으로 제안한다. 기본값으로 깔지 않는다.
- effort 슬라이더는 세션 중 못 바꾼다. 필요하면 UI 상향을 제안한다.

## PW-6. 프론트 변경은 항상 화면으로 검증

**발동:** 화면 파일(.vue/.tsx/.jsx/.svelte/.html/.css/.scss 또는 components·views·pages 아래 코드)을
편집했을 때는 **항상**. 사용자가 눈으로 본 증상을 신고했을 때는 **수정 전 재현부터**.

- 앱을 띄워서 본다. 순서: `run` 스킬 또는 프로젝트의 dev·verify 스크립트 → 웹앱이면
  `node ~/.claude/scripts/cdp.cjs launch <url>` → `cdp.cjs shot <repo>/.claude/verify/after.png` →
  스크린샷을 Read 로 열어 실제로 본다. 상태는 `cdp.cjs eval/text`, 콘솔은 `cdp.cjs console`.
- **증거는 `<repo>/.claude/verify/` 에 남긴다.** Stop 훅이 마지막 UI 편집 이후의 증거가 없으면 완료를
  막는다. 정말 띄울 수 없으면(앱 실행 불가·헤드리스) `ui-skip.md` 에 사유를 쓰고 보고에 그 사유를 적는다.
  사유 없는 skip 은 규칙 위반이다.
- 버그 신고는 **재현 → 계측 → 수정 → 같은 방법으로 재확인.** 순간적인 증상은 `cdp.cjs sample` 로
  짧은 간격 시계열을 본다.
- 외부에 진짜 쓰기가 나가는 기능은 켜지 않는다. 화면이 반응하는 지점에 같은 신호만 넣는다.
- 단위 테스트 초록불은 화면 증거가 아니다. 사용자가 같은 증상을 두 번 말하게 하지 않는다.
- 프로젝트별 실행 방법(포트, verify 스크립트, Electron 스위치)은 그 레포의 `CLAUDE.md` 에 적는다.

## PW-7. 루프 계약

일상 작업은 WP-1 대로 바로 한다. **범위가 넓고 오래 도는 자율 루프만** 계약 1회를 합의하고, 계약
안의 반복은 사람 재확인 없이 돈다.

계약에 적을 것: ① 목적(무엇이 완료인가) ② 트리거(`/goal <완료조건>` = 완료까지 도는 루프 /
`/loop <간격>` = 간격 기반 폴링·PR 돌보기(완료 조건을 평가하는 별도 판정자가 없다) / `claude -p "/goal …"` =
무인. 상세는 README '자율 루프 돌리기') ③ 범위(건드릴 것/안 건드릴 것) ④ 검증 게이트(typecheck/test/build 같은
결정적 명령) ⑤ 종료(성공 조건·시도 상한·못 하면 보고. 턴 상한은 조건 문장에 "20턴 넘으면 중단하고 남은 항목을
보고" 로 넣는다 — 평가 모델이 대화에서 판정하는 소프트 상한. 상한에 닿으면 배운 것을 work_log 에 3줄로 남기고
보고 후 멈춘다) ⑥ 진행 파일(계약 ①~⑤ 를 `<repo>/.claude/loop-contract.md` 에 적어 둔다 — 커밋 대상 아님, 끝나면
지운다. 세션 종료·중단(정체 감지·턴 상한 포함) 시점에는 `claudedocs/work_log.md`(PW-9) 항목의 3줄 안에 "미완: …"
한 줄로 남은 항목·미커밋 상태를 적는다. 루프를 이어받는 세션은 loop-contract.md, work_log 의 마지막 날짜 절,
`git log --oneline -10` 을 먼저 읽는다. `/clear` 는 활성 /goal 을 지운다).

- 병렬 루프는 워크트리로 격리한다(`worktree-worker`; 첫 디스패치는 Agent 도구 `isolation: "worktree"`, 이어서
  할 때는 `cwd: <보존된 WT>`; 디스패치 전에 본체 변경을 커밋한다 — 워크트리는 HEAD 커밋에서 분기). 워커가
  보고한 WT 경로·브랜치에서 diff 를 보고 머지한다.
- Stop 훅 `verify-on-stop.cjs` 는 매 응답 종료 시 호출되지만 이 세션이 코드 파일을 편집한 기록이 있을 때만
  typecheck·test 를 돌리고, 통과하면 기록을 지운다(결정적 회귀 게이트. 차단 3회째에는 "미해결 실패를 보고에
  명시하고 종료" 를 지시하고 다음 응답을 통과시킨다). 워크트리에 `node_modules` 가 있어야 게이트가 돈다.
  모델 판정이 필요한 완료 조건은 자체 prompt 형 Stop 훅을 만들지 말고 `/goal` 을 쓴다. 둘은 함께 돈다:
  verify-on-stop 이 회귀를 막고 /goal 평가기가 종료를 정한다.
- 계약이 있어도 PW-2 의 고위험 목록과 계약 범위 밖 작업은 사람에게 돌아온다. 게이트는 회귀만 막고
  요구사항 충족은 사람이 본다.
- 루프가 이상하게 통과·차단됐으면 `~/.claude/logs/hooks.jsonl` 을 먼저 본다.

## PW-8. 검증 없는 완료 선언 금지

"고쳤다 / 통과한다 / 됐다"는 **이 턴에서 실제로 실행한 명령의 출력**을 근거로만 말한다. 서브에이전트의
"성공"은 diff 로 직접 확인한다. 테스트 파일 삭제·skip·주석 처리·`--passWithNoTests` 직접 부착으로 초록불을
만들지 않는다(Stop 게이트는 그 트리의 첫 편집 시점 스냅샷에 테스트가 0개인 트리에서만 러너 오탐을 막으려고 그 플래그를
붙이고, 스냅샷 대비 테스트 파일 순감소는 차단한다). 실패했으면 실패했다고, 건너뛰었으면 건너뛰었다고 쓴다.

## PW-9. 작업 로그

각 레포의 `claudedocs/work_log.md` 에 작업 단위마다 한 항목을 남긴다(워크스페이스 레포가 있으면 그
루트에 하나). git log 가 못 담는 것을 담는 것이 목적이다: **왜 그렇게 했는지, 무엇을 검토하고 버렸는지,
무엇이 미커밋·보류 상태인지.**

- 형식: `## YYYY-MM-DD (요일)` 날짜 절 아래 `N. type(scope): 한 줄 요약` (feat/fix/refactor/docs/chore/ci/test/perf).
  필요하면 그 아래에 결정·근거·보류 사항을 **최대 3줄**. 과정 서술과 파일 목록 나열은 금지. 커밋했으면
  해시, 안 했으면 "커밋 미실행"을 적는다.
- 탐색이 필요할 때(과거에 비슷한 작업을 했는지, 왜 이 구조인지) 코드보다 먼저 이 파일을 Grep 한다.
- 파일이 없으면 만든다. 프로젝트 `CLAUDE.md` 가 다른 위치를 지정하면 그것을 따른다.

## 코딩 원칙 (프로젝트 규칙이 없을 때의 기본)

- **Fail Fast.** `||`, `??` 기본값은 표시 오류 방지에만. 비즈니스 값에 기본값을 넣어 오류를 숨기지 않는다.
- **상태 전이는 명시적 트리거에서만.** 조회·동기화·폴링이 상태를 바꾸면 설계가 틀린 것이다. 부분 소스로
  전체 상태를 replace 하지 말고 merge 한다. replace setter 는 누락 필드를 항상 의심한다.
- 새 함수를 만들기 전에 같은 역할의 기존 함수를 찾는다. 기존 패턴과 주석 스타일을 따른다.

## 스킬·에이전트 운용

**자동 호출(상황이 맞으면 내가 부른다):** systematic-debugging(버그·테스트 실패·이상 동작),
verification-before-completion(완료 선언 직전), receiving-code-review(리뷰 피드백을 받았을 때),
requesting-code-review(큰 기능을 끝냈을 때, `code-reviewer` 로), using-git-worktrees(플랜 실행 시작 시),
dispatching-parallel-agents(독립 작업 2개 이상). 비용이 작고 놓치면 손해가 큰 것들이다.

**명시 호출만(사용자가 부르거나 내가 제안하고 승인받는다):** `/ultra`(Workflow 는 설계상 옵트인),
brainstorming 의 architectural 경로와 writing-plans → subagent-driven-development / executing-plans 체인,
finishing-a-development-branch, writing-skills. 세리머니가 크고 세션 방향을 바꾸는 것들이다.
큰 작업이 보이면 "플랜을 써서 SDD 로 돌릴까요?" 한 줄로 제안하고 답을 기다린다.

- **brainstorming** 은 자동으로 떠도 architectural 이 아니면 설계를 한 줄 보고하고 진행한다(승인 게이트 없음).
  "질문 한 번에 하나"는 사용자만 답할 질문에만.
- **test-driven-development** 는 테스트 러너가 설정된 프로젝트에서만 강제. 없으면 typecheck·lint·
  화면 확인(PW-6)이 게이트다.
- 리뷰 디스패치(requesting-code-review, SDD)는 `general-purpose` 대신 읽기 전용 **`code-reviewer`** 로.
- `worktree-worker` = 워크트리 격리 작업자, `test-worker` = 조건을 유발해 재현·수정·재검증하는 작업자.
- `superpowers:xxx` 호출은 설치명 `xxx` 로; ui-ux-pro-max 의 search.py 는
  `~/.claude/skills/ui-ux-pro-max/scripts/search.py`(`${CLAUDE_PLUGIN_ROOT}` 는 비어 있다).
